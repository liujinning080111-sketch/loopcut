# 图像处理算法与证据边界

本版本在浏览器本机处理。自动检测是可解释的传统图像算法，没有使用抖音接口、服务器识别或语义分割模型。自动结果均作为可修正的建议。

## 1. 表情区域候选

`detectRegions` 比较相邻分析帧的 RGB 平均差，对超过阈值且反复变化的像素累计运动证据；膨胀连接相邻运动部分，再用四连通分量提取矩形、扩展边缘留白，并按运动密度和形状排序，最多返回五个候选。输出坐标为相对视频的 0–1 归一化坐标，避免高分辨率原片和小分析帧的坐标混淆。

当大量帧出现超过 38% 画面的明显变化时，算法拒绝自动给出候选。它用于降低全屏滚动、视频背景导致的误判，不代表识别出了“抖音表情”的语义。无运动、多个动画、局部滚动、仅嘴部运动而身体静止等情况可能漏检、偏小或选错；必须允许切换候选以及手动框选。

## 2. 去重复循环与保留停顿

`detectLoop` 在所选区域中提取 12×12 RGB 分块平均特征，剔除基本不变的特征通道，再比较不同周期偏移下的**整段序列**。候选必须包含至少两遍完整的相似循环，而且段内须存在足够运动幅度；只检查首尾相同不足以通过。循环长度搜索范围受采样间隔和 12 秒上限约束。

返回的 `start` 为包含边界，`end` 为排他边界。它取原时间轴的一段，不删除动画内部的连续静帧，所以角色停顿的时间仍保留。GIF 编码器可以把相同相邻画面合并为更长的延时，这与删掉延时不同。

录屏不足两遍、全静止、一次性动作、滚动、压缩噪声很大、周期过长或采样频率不足时，返回 `detected: false`；此时需要手动选段。初始自动边界精度受分析采样间隔限制，例如 8 fps 的间隔为 0.125 秒，不能宣称帧级无缝。预览、细调起止时间和对接缝的人工检查是工作流的一部分。

## 3. 背景建议与去底

`inspectBackground` 从时间轴最多七个画面的裁剪边缘取色，以量化颜色众数估计固定背景色，并检查各帧边缘一致性和主体占比。只有边缘足够一致且存在可分离主体时才建议透明，否则建议保留矩形。录屏已经将透明图与评论区背景合成，因此原始透明度已丢失，无法仅凭录屏保证重建原图。

`removeBackground` 从四周边缘开始，只去除与目标背景色接近且四连通的像素。颜色容差使用 RGB 欧氏距离，推荐初始值 30，内部限制 0–160；增大容差更容易去除压缩色块，也更可能损伤浅色或近背景色主体。与边缘不连通的同色区域被保留，避免把眼白等封闭细节直接挖空。

透明度输出是 0/255，符合 GIF 的二值透明限制。模糊边缘、阴影、与背景同色且接触边缘的主体、复杂纹理背景不能保证抠图质量；保留矩形背景始终可选。背景模式为“智能”时只是在这两个可用模式间给出保守选择，不是恢复原始素材。

## 4. 自动化验证

`tests/vision.test.ts` 使用可复现的人工像素序列验证：两遍完整循环、带停顿的循环时长、静止前奏、小色差、仅首尾相同的反例、静止/漂移拒绝、选区外运动隔离、局部运动候选、全屏变化拒绝、边缘颜色判断、连通去底和封闭同色细节保留、裁剪坐标边界。

这些测试验证算法的确定行为，不能证明真实抖音素材上的检测准确率。交付前仍须用用户授权的实际录屏及目标 iPhone 按 `DEVICE-TESTS.md` 验收；没有采集数据集，也没有宣称通用准确率。
