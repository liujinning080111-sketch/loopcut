## 本轮：原尺寸 / 原时间轴与四角裁剪

本轮默认格式仍为 **GIF**，默认采用原裁剪尺寸和源 PTS 时间轴，加入可选 APNG，以及四角缩放、框内移动的裁剪操作。

本地最终复验：**52 / 52 项单元测试、生产构建与差异检查均通过**。浏览器共 **16 项流程通过**，由 Chromium 与桌面 WebKit iPhone 布局分别执行：裁剪 6 项、原帧导出 4 项、原有应用流程 6 项；其中应用流程 6 项已在最终阶段再次运行通过。此处记录本地验证，不代表新公网版本或真实 iPhone 已验收。

| 检查 | 实际覆盖与结果 |
| --- | --- |
| 原尺寸与原帧 GIF | 使用项目原生绘制的 **1280 × 32、60 fps、0.5 秒 / 30 帧** H.264 素材，含 B 帧。网页默认尺寸 / 帧率选项均为原始模式；导出 GIF 独立解码后仍为 1280 × 32，30 个黑白编码帧号按顺序完整对应 **0–29**，没有落回 1024 px 缩图上限，也未抽帧或重复替代帧。文件记录的累计延时为 **500 ms**。 |
| APNG 原帧导出 | 同一素材导出 APNG，独立解析 PNG 动画块并解压像素，30 帧编号同样完整对应 **0–29**，每帧延时均为 **1/60 秒**。下载文件扩展名为 `.png`；切换格式使旧结果失效。 |
| 无 WebCodecs 兼容回退 | 在页面加载前禁用 VideoDecoder，确认界面显示兼容解码提示。该合成素材经 video seek 回退后，GIF 解码仍为原尺寸、连续 30 帧编号和 500 ms 文件延时。此结果仅证明已测浏览器与素材，不推广为所有 Safari / HEVC 输入逐帧精确。 |
| 不可表达的 GIF 边界时长 | 60 fps 素材选取 0–0.12 秒，末尾残帧短于 GIF 的 0.01 秒时间单位时，页面明确停止并提示，结果保持隐藏、编辑控件可继续使用；没有静默丢掉尾帧。 |
| 四角与框内操作 | 四个角调整时保留对角锚点，框内拖动不改变宽高；移动被限制在图像内，框外空白拖动不重建裁剪框。角点交互区域至少 44 px，方向键与 Shift 加速移动生效。 |
| 取消手势 | Chromium 使用真实协议触摸取消；WebKit 使用真实鼠标捕获后派发对应 pointercancel。均恢复手势前矩形、释放 pointer capture，Escape 也能恢复。WebKit 此项不等同于真实 iPhone 触摸拖动。 |
| 原有应用流程 | 两个浏览器继续覆盖录屏导入、区域与循环识别、预览、手动修正、矩形 / 透明 GIF、下载、取消、损坏文件恢复、窄屏和离线应用壳，共 6 项。 |

单元测试覆盖纯裁剪几何、源时间排序、VFR 停顿与边界截断、显式尺寸 / 帧率缩减、GIF 逐帧保留和资源拒绝，以及 APNG RGBA、连续 alpha、有理数延时、逐帧缓冲复用、取消及输出预算。测试输入与内容见 `tests/`；本节未把有限合成序列的通过等同于任意真实录屏都正确。

编号素材、像素读取方法和可复现生成脚本见 [素材说明](../tests/fixtures/README.md)。该素材源文件的 SHA-256 为 `ed9a0acb63a6bd668fb5436ce04bc9dc5d446d78941b3b4bf92fc2f3c7beeb8c`。

GIF 中写入 500 ms 不保证 Safari 或微信实际以 500 ms 播放：GIF 延时需按 10 ms 量化，60 fps 对应的部分 10 ms 延时可能被播放器延长。APNG 的精确 1/60 秒字段也不证明所有设备实时渲染都不掉帧。APNG 的无损对象是传入编码器的解码后 8-bit RGBA；不涵盖原视频压缩、HDR 映射或浏览器色彩转换。

**本轮未验证真实 iPhone 硬件、照片保存、系统分享接收、微信表情导入，尚不能声称新版已在这些环境通过。** 桌面浏览器回归和本地构建也不证明本轮代码已完成 GitHub Pages 公开部署；最终提交、Actions 与公网资源核对应另行记录。历史截图 / 导出示例保持下述原版本说明。

## 高清修订历史记录

本地验证：**22 项单元测试、Chromium 3 项、桌面 WebKit iPhone 布局 3 项全部通过**。

- 原生重绘 1080 × 1920 / 30 fps 示例，已知表情画布 600 × 600，不是将旧视频放大。
- 编辑预览直接读取原视频，测试确认原生表情的预览长宽均不少于 500 像素；按 0 / 0.5 / 2 秒检查运动与完整循环，等待实际绘制完成后读取像素。
- 600 像素表情默认按原画尺寸导出，没有落回旧的 320 上限；用户显式选 320 后实际输出 320。
- 640 × 480 原生黑白单像素细节编码后独立解码，像素逐个一致；这是有限颜色测试，不代表任意视频 GIF 无损。
- 透明 / 矩形、下载字节、非整帧终点、取消恢复和离线用例均继续通过。
- 文件尺寸上限针对实际压缩输出检查；超过 16 MiB 明确失败，不悄悄降低分辨率。

尚未以真实 iPhone 硬件测试高清模式的内存、系统分享或微信接收。

## 证据边界

1. **桌面 WebKit 模拟 iPhone 视口不等于 iPhone 真机验证。** 原生照片选择器、设备 HEVC 解码、低内存行为、iOS 系统分享、主屏幕安装、锁屏和长时间使用仍需按 [真机测试清单](DEVICE-TESTS.md) 验收。
2. 自动检测验证使用自行绘制的合成 MP4 和单元测试序列，**尚不能给出真实抖音录屏识别准确率**。滚动、多个运动区域、遮挡、复杂背景、只有半个循环时应检查置信度并使用手动修正。
3. 分享按钮按 Web Share 用户手势要求实现；网页不会静默写入照片图库。分享 Promise 成功也无法证明文件已存入照片。实际微信导入接受情况没有在本地浏览器测试中验证。
4. 本地生产构建、浏览器测试和子路径验证不会自动证明公网发布成功。还需要实际托管 URL、GitHub Actions 部署结果及公网访问确认。
