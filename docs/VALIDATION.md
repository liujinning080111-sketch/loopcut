# 验证记录

日期：2026-10-21。以下分别记录高清修订与初版的实际验证，公网部署以对应提交的 Actions 结果及真实地址检查为准。

## 高清修订

本地验证：**22 项单元测试、Chromium 3 项、桌面 WebKit iPhone 布局 3 项全部通过**。

- 原生重绘 1080 × 1920 / 30 fps 示例，已知表情画布 600 × 600，不是将旧视频放大。
- 编辑预览直接读取原视频，测试确认原生表情的预览长宽均不少于 500 像素；按 0 / 0.5 / 2 秒检查运动与完整循环，等待实际绘制完成后读取像素。
- 600 像素表情默认按原画尺寸导出，没有落回旧的 320 上限；用户显式选 320 后实际输出 320。
- 640 × 480 原生黑白单像素细节编码后独立解码，像素逐个一致；这是有限颜色测试，不代表任意视频 GIF 无损。
- 透明 / 矩形、下载字节、非整帧终点、取消恢复和离线用例均继续通过。
- 文件尺寸上限针对实际压缩输出检查；超过 16 MiB 明确失败，不悄悄降低分辨率。

尚未以真实 iPhone 硬件测试高清模式的内存、系统分享或微信接收。

```sh
npm test
npm run test:e2e
```

## 证据边界

1. **桌面 WebKit 模拟 iPhone 视口不等于 iPhone 真机验证。** 原生照片选择器、设备 HEVC 解码、低内存行为、iOS 系统分享、主屏幕安装、锁屏和长时间使用仍需按 [真机测试清单](DEVICE-TESTS.md) 验收。
2. 自动检测验证使用自行绘制的合成 MP4 和单元测试序列，**尚不能给出真实抖音录屏识别准确率**。滚动、多个运动区域、遮挡、复杂背景、只有半个循环时应检查置信度并使用手动修正。
3. 分享按钮按 Web Share 用户手势要求实现；网页不会静默写入照片图库。分享 Promise 成功也无法证明文件已存入照片。实际微信导入接受情况没有在本地浏览器测试中验证。
4. 本地生产构建、浏览器测试和子路径验证不会自动证明公网发布成功。还需要实际托管 URL、GitHub Actions 部署结果及公网访问确认。
