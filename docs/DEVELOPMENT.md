# 开发与测试

## 架构

LoopCut 是 Vite + TypeScript 的无框架静态 Web App。Mediabunny 读取本地容器与源帧时间轴，视频解码依赖浏览器 WebCodecs / 原生视频能力，GIF / APNG 编码由独立 Web Worker 执行；不需要后端、云端推理或多线程 WebAssembly。

```text
本地 File
  → blob URL / HTMLVideoElement
  → 低分辨率顺序采样
  → 运动区域候选 + 所选区域周期分析 + 背景建议
  → 用户确认裁剪、时间与背景
  → 独立预览视频从原始录屏解码画面
  → 读取源 PTS，按原裁剪尺寸逐帧解码（或用户主动指定缩减）
  → 可选去背景
  → Worker 逐帧 GIF 量化编码 / APNG RGBA 编码
  → Blob / File
  → 用户点击分享、下载或打开
```

分析帧仅用于计算建议。编辑预览使用独立视频元素读取原始录屏，避免预览播放与分析 / 导出 seek 互相影响；最终导出也从源视频重新裁剪取帧。192 px 分析缩略图不得作为编辑预览或最终导出的图像来源。

| 路径 | 责任 |
| --- | --- |

| `src/media/video.ts` | 本地视频载入、元数据、顺序 seek、Canvas 取帧与取消 |
| `src/media/source-timeline.ts` | 本地容器时间轴、源 PTS 调度、WebCodecs 解码与兼容回退 |
| `src/media/limits.ts` | 原尺寸计算与资源上限；超出时失败，不能暗中缩减 |
| `src/media/gif-core.ts` | 可测试的 GIF 编码器、时间量化与重复帧合并 |
| `src/media/gif.worker.ts` | Worker 消息协议与编码执行 |

## 参数与资源边界

- 自动分析采样为 8 fps，单次最多 24 秒，最多 192 张分析帧，最长边 192 px。
- 最终导出最多 12 秒。默认原尺寸按源裁剪整数像素输出，不自动压到 1024 px；可由用户主动选 640 / 480 / 320 px，保持比例且不放大小图。
- 默认使用源容器的每帧 PTS 调度，保留 VFR 不等间隔；界面 FPS 摘要不是导出时钟。只有用户选择 10 / 15 / 20 / 30 fps 时才均匀重采样。
- 单边上限 8192 px、单帧上限 16,777,216 像素、片段上限 1440 帧、生成文件上限 128 MiB。超出任何一项即停止并提示，不能自动缩图、抽帧或降低帧率。这些是工具保护值，不是微信接收限制，也不是全进程 RAM 上限。
- 导入文件上限 256 MB。限制文件大小不等于限制了解码内存；高分辨率、长 GOP 或特殊编码素材仍可能在设备上失败。
- 编码采用流式输入，每帧等待 Worker 确认后才发送下一帧，避免同时积压全部 RGBA 数据。压缩输出随编码增长；不能声称总内存恒定。
- 编码器额外限制单帧尺寸、帧数据长度、时长及总输入帧数。这些是内部防护；界面允许范围仍以上述设置为准。
- 应在成功、失败、取消、重新导入时清理 Worker、事件监听和 blob URL。未完成的旧任务不能覆盖新素材结果。

## 图像处理

### 区域候选

对连续分析帧求 RGB 差异，统计持续出现的运动像素；膨胀后取连通区域并加留白，依据面积、比例和运动复现度排序。全屏大幅变化时保守拒绝自动判断，降低评论滚动或背景视频被误当成表情的风险。

这是一种运动候选算法，不是识别表情语义的模型。只有眼睛或嘴巴运动时可能框不全静态身体；因此所有候选都需要可预览、可替换、可手动修正。

### 裁剪坐标

`Rect` 使用相对解码后视频的归一化坐标：

```ts
interface Rect {
  x: number;      // 左边位置 / 视频宽度
  y: number;      // 顶边位置 / 视频高度
  width: number; // 选区宽度 / 视频宽度
  height: number;// 选区高度 / 视频高度
}
```

每项有限且非负，宽高大于零，`x + width`、`y + height` 不超过 1。触摸坐标先根据预览实际显示区域换算，不能直接把 CSS 像素当源视频像素。裁剪框提供四角缩放和框内拖动；四角仍约束为矩形，不作透视变换。拖动、数字调整、预览、周期分析和导出共享同一矩形状态；切换横竖屏后仍保持同一内容。最终 crop 在旋转 / 翻转后的显示坐标中取整，不把原始编码方向与预览方向混用。

### 完整循环

在已选区域内生成缩小后的颜色特征，仅使用确实随时间变化的特征维度。比较候选周期前后的整段序列，要求至少两个完整片段匹配并含有足够运动，再优先选择有支持的较短基础周期。

不能因为首帧和末帧相同就宣布找到了完整循环。静止图、变化过小或数据不足时返回未检测状态和手动范围提示。当前分析时间分辨率约为 1/8 秒，最终帧率提高不能自动补回周期判断精度；手动起止和循环预览用于修正。

### 背景选择与去除

从所选区域多张代表帧的边缘估计主背景色，检查各帧边缘的一致性和可见主体比例。边缘复杂、变化明显或主体贴边时，智能模式倾向保留矩形。

透明模式从图像边缘出发，仅移除与背景色接近且边缘连通的像素。这样可以保留被主体包围的同色区域，例如白眼睛；仍可能损伤与背景同色且连到边缘的主体。容差采用 RGB 欧氏距离，范围受限；用户必须可以降低容差或改回矩形。

录屏中已经合成的阴影、半透明像素或复杂背景无法被可靠反演。该算法不是通用人像抠图或原透明 GIF 恢复。

## 源时间轴、视频解码与动画编码

Mediabunny 1.62.0 使用 BlobSource 读取本地 MP4 / QuickTime MOV / WebM。EncodedPacketSink 以 metadataOnly 枚举样本，保存实际 PTS / duration 并按呈现顺序建立调度。不能根据录屏时长、文件扩展名、rVFC 回调频率或平均 FPS 生成所谓“原帧”时间轴。VFR 应保留不同的呈现间隔；首尾落在帧中间时，仅保留该帧与选区相交的时长。

CanvasSink 自动应用支持的旋转 / 翻转元数据，crop 位于显示像素空间。WebCodecs 可用时，解码结果时间戳必须与源调度对应；缺帧、错误对应或数量不符时停止，不能跳过后继续。无法使用 WebCodecs 时，兼容回退按源时间轴 seek，并在界面说明帧定位取决于浏览器；此路径不能宣称严格逐帧对应。Mediabunny 支持的 edit list 并不涵盖任意剪辑时间轴，捕获不支持的编辑警告并拒绝原帧模式；不可把简单样本枚举等同于所有多段/速率编辑都正确。

视频元素保持静音与内联播放，载入后检查元数据和当前帧就绪状态。改变 `currentTime` 后等待 seek 完成及可绘制画面，整个过程顺序执行并支持 AbortSignal；每次等待有超时，错误反馈应区分无法解码、无法读取和超时。编辑预览与分析 / 导出分别使用视频元素，不能用播放预览的 seek 覆盖正在导出的取帧位置。

GIF 编码用 `gifenc` 量化索引颜色。保留独立透明索引，透明像素不会与不透明黑色混淆；帧处置策略清除上一帧，避免移动主体拖影。GIF 时长按 10 ms 单位累计量化，减少总时长舍入偏差，但不能逐帧精确表示任意源时间轴。60 fps 常需 10 / 20 ms 交替，当前 WebKit 对小于 11 ms 的图像动画延时会改成 100 ms，因此实际播放可能明显变慢。不能把“所有帧已写入”说成“所有播放器原速播放”。短于格式可表达范围的输入应明确失败或由用户选择别的格式。

APNG 使用 PNG 的 RGBA 色型，保存传入编码器的解码后 8-bit RGBA，不做 GIF 的 256 色量化。延时由两个 16-bit 整数的秒分数表示，常见 30 / 60 / 29.97 fps 可表达；一般 VFR 的有理数可能超出字段范围，精度受编码器实际分数处理限制。极高帧率还受播放器短延时钳制与屏幕刷新影响。Canvas 色彩转换、HDR 到 SDR 映射及录屏先前的有损压缩均不在 APNG 无损承诺内。

默认原帧导出保留每一个选区内源帧，包括重复画面和其停顿；不自动合并来改变帧数。循环去重仅选择一轮时间段。GIF 核心保留可选的相邻重复帧合并能力，若其他调用启用，必须累加延迟；不能把它与默认保留全部帧混为一谈。

编码完成后再构造正确 MIME 的 File（GIF 为 image/gif；APNG 按生成文件标注）。分享按钮的点击处理程序应先检查最终文件的 `canShare`，随即调用 `navigator.share`；不要把编码放在点击处理中的长异步链之后再请求分享。用户取消分享不应清除导出结果，也不能被记录为“已存入照片”。

## 开发命令

需要 Node.js 22.12+；使用锁文件固定依赖安装结果。

```sh
npm ci
npm run dev
npm test
npm run build
npm run preview
```

`npm run check` 汇总单元测试与生产构建。端到端测试另外运行：

```sh
npx playwright install
npm run test:e2e
```

Linux CI 若缺少浏览器系统库，可使用 `npx playwright install --with-deps`。测试应针对构建后的实际浏览器流程和静态资源路径，不应只断言 DOM 元素存在。

## 部署与维护

项目使用相对资源路径，适配 GitHub Pages 的仓库子目录。worker、manifest、图标、Service Worker 注册与缓存条目必须采用同一基路径，不能出现只在根路径可用的硬编码。

Service Worker 缓存应用壳，不负责长期保存用户录屏或在后台持续转码。新版本发布后检查资源版本一致性和旧缓存清理；不要在用户处理过程中强制刷新。完整部署步骤见 [DEPLOYMENT.md](./DEPLOYMENT.md)，平台边界与官方来源见 [COMPATIBILITY.md](./COMPATIBILITY.md)。

分发时保留 `public/THIRD_PARTY_NOTICES.txt`：gifenc 为 MIT；Mediabunny 1.62.0 为 MPL-2.0，其中已附完整许可证与对应固定版本源码链接。修改受 MPL 覆盖的库文件时，应同时提供相应修改的源代码；不要把它误标为 MIT。
