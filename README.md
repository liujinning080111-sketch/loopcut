# LoopCut · 录屏变表情

把抖音评论区录屏导入浏览器，选择表情区域，提取一遍循环，导出可分享的 GIF，也可保存 APNG。面向 iPhone Safari 和“添加到主屏幕”后的 PWA，所有视频与图像处理在本机完成。

支持自动区域候选、循环检测、矩形 / 透明 / 智能背景、预览、四角裁剪与框内移动、起止时间修正、GIF / APNG 导出、系统文件分享及下载。默认 GIF 使用原裁剪尺寸和源帧时间轴，不自动缩图或抽帧；GIF 本身仍有颜色和时间精度限制。自动识别是可修正的建议：评论滚动、复杂背景、多个动画或不足两遍循环的录屏可能需要手动调整。

**网页不会无权限写入照片图库。** GIF 生成后，用户点击分享并在系统菜单中选择可用的保存方式；分享菜单、照片保存与微信接收仍需在具体 iPhone / 微信版本中验证。

GIF 默认增加无损体积优化，只有最终文件 **不超过 500,000 字节（500 KB，十进制）** 才显示保存 / 下载。优化只改变 GIF 保存重复像素和调色板的方式，不额外减色、不缩尺寸、不删除帧，也不改变已经写入 GIF 的帧延时；使用多个编码候选，核对连续两轮的完整合成画面后只选更小结果。这里的无损相对于常规 GIF 编码结果，不能消除 GIF 本身的颜色及时间精度限制。

复杂或很长的动画可能无法在保持这些条件的同时小于 500 KB。此时页面会显示优化后的大小并停止保存，需自行缩短片段或收紧裁剪范围；不会悄悄降低画质。500 KB 是本项目按用户要求设置的上限，不是所有微信版本保证接受的标准。

## 本地运行

需要 Node.js **22.12 或更高版本**。在本项目目录运行：

```sh
npm ci
npm run dev
```

打开终端显示的本地地址。手机与电脑在同一网络时可以访问开发服务器的局域网地址，但 HTTP 局域网地址不具备完整的安全上下文能力；完整 PWA、文件分享与离线验收使用 HTTPS 部署地址。

```sh
npm test
npm run build
npm run preview
```

`build` 会进行 TypeScript 检查、构建静态资源并生成离线缓存脚本，产物在 `dist/`。第一次运行端到端测试前，安装测试所需浏览器：

```sh
npx playwright install
npm run test:e2e
```

## 使用流程

1. 在抖音评论区固定画面，录下目标表情至少两遍，最好三遍，避免滑动或遮挡。
2. 导入已下载到手机本机的视频，运行自动分析。
3. 检查区域候选，拖动裁剪框四角改变大小，拖动框内移动位置；也可用数字微调，确认保留完整动作范围。
4. 预览一遍循环，调整起止时间，检查首尾衔接与停顿时长；终点按视频真实边界限制，不因显示舍入越过片尾。
5. 选择智能、透明或矩形背景。透明模式可调整容差；浅色主体受损时降低容差或保留矩形。
6. 默认生成原尺寸、原帧时间轴 GIF；需要保留完整 RGBA 画面与更精细帧时序时可选 APNG。只有主动选较小尺寸或固定帧率时才缩减。生成后点击分享、下载或打开结果。
7. 按当前 iOS / 微信界面可用的路径保存并导入个人表情，重新检查动画与透明效果。

## 处理范围

| 设置 | 当前范围 |
| --- | --- |
| 导入文件 | 最多 256 MB；实际解码能力由设备决定，优先 H.264 MP4 |
| 自动分析 | 单次最多 24 秒、8 fps、分析画面最长边 192 px |
| 编辑预览 | 使用独立视频元素读取原始录屏，不以分析缩略图作为预览画面 |
| 动画片段 | 最多 12 秒 |
| 输出尺寸 | 默认原裁剪像素尺寸，不缩放；可主动选 640 / 480 / 320 px，保持比例且不放大小图 |
| 输出时间轴 | 默认读取源文件每帧呈现时间（PTS），保留所有选区帧；GIF 再按 10 ms 精度协调延时，可主动选 10 / 15 / 20 / 30 fps |
| GIF 保存上限 | 最终无损优化后的文件最多 500,000 字节；超限不提供保存链接，不自动降画质 |
| 资源保护 | 单边最多 8192 px、单帧最多 16,777,216 像素、片段最多 1440 帧、中间编码 / APNG 最多 128 MiB；WebCodecs 路径的完整源帧也须满足尺寸预算，超出即停止，不暗中缩图或抽帧 |
| 格式 | 默认 GIF；可选 APNG，无损保存交给编码器的解码后 8-bit RGBA |
| 背景 | 智能建议、保留矩形、边缘连通的纯色背景去除 |

分析分辨率只用于快速寻找区域与循环，编辑预览和导出分别从原始录屏取图。原尺寸模式按视频显示方向裁剪到整数像素，不设 1024 px 的自动缩小上限；它不能恢复录屏中本来没有的细节。内置示例使用原生 1080 × 1920 画面和 600 × 600 表情画布。另有 [1280 px / 60 fps 编号测试素材](./tests/fixtures/README.md)，用于验证尺寸与逐帧对应，未用它冒充真机验收。

原帧解码先生成已按显示方向旋转 / 翻转的完整 Canvas，再按选区读取像素或从 Canvas 缩放，绕过 WebKit 的 VideoFrame 源矩形裁剪缺陷，避免整幅录屏被压进裁剪框。因此，即使选区很小，完整源帧也需在 16,777,216 像素预算内。[WebKit 源码](https://github.com/WebKit/WebKit/blob/main/Source/WebCore/html/canvas/CanvasRenderingContext2DBase.cpp#L1832-L1863)

GIF 每个活动调色板最多 256 色，只能完全透明或不透明，帧延时以 0.01 秒记录。导出会对整段序列分配延时，每帧至少 10 ms；短头帧、尾帧或 VFR 短帧不会因此被拒绝或丢弃。可行时，文件总时长取原总时长最接近的 10 ms；若保留全部帧所需的最低时长更长，则明确显示延长后的实际文件时长。局部节奏仍可能改变，且 Safari 还可能把 10 ms 延时进一步延长，实际播放比文件记录更慢。APNG 可保留更精细的有理数延时和连续透明度，但极高帧率仍受播放器限制，HDR 也可能经浏览器映射为 SDR；两者都不是原视频字节无损备份。APNG 不保证能作为微信个人表情。详见 [格式与播放边界](./docs/COMPATIBILITY.md#原尺寸与帧时序的边界)。

处理时保持页面前台。资源保护值不是设备一定能承受的内存预算，也不是微信保证接受的文件大小。无法逐帧解码的浏览器会明确显示兼容解码提示：仍按源时间轴请求画面，但实际帧定位由浏览器决定。无法可靠读取时间轴时停止原帧模式，手动指定帧率不称为原帧率。

GitHub Pages 设置、自动部署与子路径注意事项见 [部署说明](./docs/DEPLOYMENT.md)。仓库提供部署配置；**只有工作流成功且真实地址可访问才算上线，本地构建不等于已部署。**

在 iPhone Safari 打开部署后的 HTTPS 地址，使用分享菜单“添加到主屏幕”；如果系统显示“作为 Web App 打开”，启用后添加。首次完整加载后可缓存应用资源以供离线使用；系统仍可能回收缓存，原录屏和未保存结果不保证跨会话保留。

## 隐私

项目不提供录屏上传处理服务，不需要登录或 API 密钥。视频、抽帧与动画生成在当前设备处理；不要把自己的录屏放进公开仓库。静态托管服务仍可能记录网站访问日志，具体边界见兼容性文档。运行时依赖的许可证和固定版本源码链接见 [第三方声明](./public/THIRD_PARTY_NOTICES.txt)。
