# LoopCut · 录屏变表情

把抖音评论区录屏导入浏览器，选择表情区域，提取一遍循环，导出可分享的 GIF。面向 iPhone Safari 和“添加到主屏幕”后的 PWA，所有视频与图像处理在本机完成。

支持自动区域候选、循环检测、矩形 / 透明 / 智能背景、预览、手动裁剪与起止时间修正、GIF 导出、系统文件分享及下载。自动识别是可修正的建议：评论滚动、复杂背景、多个动画或不足两遍循环的录屏可能需要手动调整。

**网页不会无权限写入照片图库。** GIF 生成后，用户点击分享并在系统菜单中选择可用的保存方式；分享菜单、照片保存与微信接收仍需在具体 iPhone / 微信版本中验证。

## 本地运行

需要 Node.js **22.12 或更高版本**。在本项目目录运行：

```sh
npm ci
npm run dev
```

打开终端显示的本地地址。手机与电脑在同一网络时可以访问开发服务器的局域网地址，但 HTTP 局域网地址不具备完整的安全上下文能力；完整 PWA、文件分享与离线验收使用 HTTPS 部署地址。

```sh
npm test
npm run build
npm run preview
```

`build` 会进行 TypeScript 检查、构建静态资源并生成离线缓存脚本，产物在 `dist/`。第一次运行端到端测试前，安装测试所需浏览器：

```sh
npx playwright install
npm run test:e2e
```

## 使用流程

1. 在抖音评论区固定画面，录下目标表情至少两遍，最好三遍，避免滑动或遮挡。
2. 导入已下载到手机本机的视频，运行自动分析。
3. 检查区域候选，必要时手动画框；确认只保留目标表情的完整动作范围。
4. 预览一遍循环，调整起止时间，检查首尾衔接与停顿时长。
5. 选择智能、透明或矩形背景。透明模式可调整容差；浅色主体受损时降低容差或保留矩形。
6. 选择输出尺寸与帧率，生成 GIF，再点击分享、下载或打开结果。
7. 按当前 iOS / 微信界面可用的路径保存并导入个人表情，重新检查动画与透明效果。

## 处理范围

| 设置 | 当前范围 |
| --- | --- |
| 导入文件 | 最多 256 MB；实际解码能力由设备决定，优先 H.264 MP4 |
| 自动分析 | 单次最多 24 秒、8 fps、分析画面最长边 192 px |
| 编辑预览 | 使用独立视频元素读取原始录屏，不以分析缩略图作为预览画面 |
| GIF 片段 | 最多 12 秒 |
| GIF 尺寸 | 默认原画尺寸，最长边上限 1024 px；另可选 640 / 480 / 320 px，保留比例，不放大小图 |
| GIF 帧率 | 10 / 15 / 20 / 30 fps，默认 20 fps |
| GIF 文件 | 上限 16 MiB；超出时需降低尺寸、帧率或缩短片段 |
| 背景 | 智能建议、保留矩形、边缘连通的纯色背景去除 |

分析分辨率只用于快速寻找区域与循环，编辑预览和导出分别从原始录屏取图。原画模式保留源裁剪的像素，超过 1024 px 时按比例缩小；它不能恢复录屏中本来就没有的细节。内置示例已使用原生 1080 × 1920 画面和 600 × 600 表情画布，便于检查导出尺寸与细节。

处理时保持页面前台。文件太大或设备较慢时，先在照片中裁短录屏，或降低输出尺寸与帧率。GIF 仍需颜色量化，且仅支持完全透明 / 完全不透明；原画尺寸不表示颜色或半透明边缘无损。16 MiB 是本工具的资源保护上限，不是微信保证接受的大小。

## iPhone 安装与部署

GitHub Pages 设置、自动部署与子路径注意事项见 [部署说明](./docs/DEPLOYMENT.md)。仓库提供部署配置；**只有工作流成功且真实地址可访问才算上线，本地构建不等于已部署。**

在 iPhone Safari 打开部署后的 HTTPS 地址，使用分享菜单“添加到主屏幕”；如果系统显示“作为 Web App 打开”，启用后添加。首次完整加载后可缓存应用资源以供离线使用；系统仍可能回收缓存，原录屏和未保存结果不保证跨会话保留。

## 隐私

项目不提供录屏上传处理服务，不需要登录或 API 密钥。视频、抽帧与生成 GIF 在当前设备处理；不要把自己的录屏放进公开仓库。静态托管服务仍可能记录网站访问日志，具体边界见兼容性文档。
